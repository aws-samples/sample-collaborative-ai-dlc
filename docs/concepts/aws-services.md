# AWS services

This page lists the AWS services provisioned by the Terraform code under `terraform/` or called by the platform, including optional integrations configured outside the stack. Use it to scope deployment permissions, service control policies, Region availability checks, and cost reviews. For how these services fit together, see [Architecture](architecture.md).

Services are grouped by their main role in the platform. Optional features and configuration requirements are noted alongside each service.

## Notes

### Amazon Bedrock model invocation

Claude Code, OpenCode, and Codex support two authentication modes. **Keys** mode uses the Bedrock API key resolved from the credential hierarchy. **IAM** mode uses temporary credentials for a dedicated external inference role assumed by the credential broker. That role grants Bedrock model access, including Bedrock Mantle for Codex; the AgentCore runtime's own role has no model-invocation permissions or automatic fallback. Kiro uses its own API key in either mode. See [Agent authentication](../getting-started/prerequisites.md#agent-authentication) and [Bedrock IAM setup](../using-the-platform/bedrock-iam.md).

### Amazon SQS

The only queue is the dead-letter queue `<project_name>-intents-attachment-events-dlq-<environment>`. It belongs to the intent attachment promotion flow: an S3 object-created event under `intent-attachments/staging/` triggers an EventBridge rule that invokes the `intents` Lambda. An event lands in the queue when EventBridge cannot deliver it (12 attempts within one hour) or when the Lambda still fails after two retries. No application code reads the queue, and messages expire after 14 days. Inspect it manually when an attachment stays in staging.
