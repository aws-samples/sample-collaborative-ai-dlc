# External Code-Generation Handoff

An external code-generation handoff lets a developer complete one unit's `code-generation` stage in a local IDE, CLI, hosted workspace, or remote agent, then return the result to the running intent.

Unlike a general [workspace export](exporting-workspaces.md), this is a controlled round trip. Collaborative AIDLC keeps the unit parked, validates the pushed source revisions and required documents, imports the result, and resumes the unit's remaining workflow stages.

## Start an external handoff

The option appears on a required stage review immediately before `code-generation` when the unit has source repositories available.

1. Review the current stage and choose **Approve and develop externally**.
2. The unit moves to an **External code generation** gate.
3. Choose a harness with the small arrow:
   - Claude
   - Codex
   - Kiro CLI
   - Kiro IDE
   - OpenCode
4. Choose **Download workspace**.
5. Review the unit, repositories, and assigned branches, then choose **Download code-generation workspace**.

Choosing a harness only changes the selected workspace format. The download does not start until you use the adjacent download button and confirm.

The handoff is assigned to the user who selected external development. Only that user can submit the completed result.

## What the workspace is for

The downloaded workspace is scoped to the selected unit and its `code-generation` stage. It includes the pinned workflow context, completed upstream artifacts, repository assignments, continuation instructions, and harness-specific AI-DLC files.

Complete only code generation in this workspace. Later construction, review, build, test, and delivery stages remain owned by Collaborative AIDLC and run after the handoff is accepted.

## Work on the assigned branches

The confirmation dialog and handoff card list one assigned branch per repository. From each repository:

1. Check out or clone the assigned branch.
2. Make the source changes for the unit.
3. Review and commit only the intended changes.
4. Push the commit to the exact assigned branch.

For a multi-repository unit, push every listed repository before submitting the handoff.

The platform records the repository revision from which the handoff started. At submission, it verifies that each assigned branch exists and that its current head descends from that original revision.

## Produce the required documents

The native code-generation stage must produce both:

- `code-generation-plan.md`
- `code-summary.md`

Keep the filenames and AI-DLC document structure generated by the harness. Each file must contain valid text and must not exceed 256 KiB.

The handoff card includes a command for locating both files in the downloaded workspace.

## Return the completed unit

After all source changes are pushed:

1. Return to the intent's **External code generation** gate.
2. Choose **Upload plan** and select `code-generation-plan.md`.
3. Choose **Upload summary** and select `code-summary.md`.
4. Choose **Submit**.

The platform validates:

- The handoff still belongs to the current stage attempt.
- The submitting user owns the handoff.
- Both required documents are present, non-empty, valid structured AI-DLC documents, and within the size limit.
- Every assigned repository branch has a valid head.
- Every submitted branch head descends from the revision assigned at handoff time.

If validation succeeds, the platform freezes the submitted branch heads, imports both documents as the unit's code-generation artifacts, marks the external `code-generation` stage successful, and resumes the unit.

!!! note "What is synchronized back"

    Only commits pushed to the assigned branches and the two submitted documents are returned to the intent. Other local decisions, approvals, conversations, or workspace state are not added to its traceability history.

## Fix a rejected submission

Validation findings appear on the handoff card and the task remains pending. Correct the reported issue, select the documents again, and resubmit.

Common findings include:

- A required document is missing, empty, too large, or does not match the expected AI-DLC structure.
- An assigned branch was not pushed or its head cannot be read.
- A branch no longer descends from its assigned base revision.
- The handoff belongs to an older stage attempt after a retry, rewind, or cancellation.
- The unit is assigned to another developer.

Refresh the intent before retrying if the handoff is reported as stale.

## Return to managed execution

Choose **Cancel external development** if you no longer want to complete the handoff outside the platform. After confirmation, Collaborative AIDLC closes the external task and runs the unit's `code-generation` stage in its managed agent runtime.

Cancelling external development does not cancel the intent.
