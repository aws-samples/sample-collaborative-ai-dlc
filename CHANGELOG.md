## [Unreleased]

## [2.3.1] - 2026-11-13

Hotfix that keeps AgentCore microVM runtimes on platform V1 ([#758](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/758)).

### Fixed

- The Standard runtime and newly created managed microVM runtimes now explicitly select AgentCore platform `V1`. AWS is changing the default for new runtimes to V2, which the platform has not yet qualified ([#719](https://github.com/aws-samples/sample-collaborative-ai-dlc/issues/719)). Without the setting, new deployments and new managed environments would be created on V2 once that default changes. Instances environments keep their capacity-provider configuration.

### Changed

- Terraform requires AWSCC provider 1.103.0 or later, and the AWS SDK ranges move to 3.1133.0. These are the first versions that support the platform version setting.

### Notes

- **Upgrade from v2.3.0.** The next `terraform apply` applies the V1 setting to the existing Standard runtime. Existing managed environment revisions keep their runtime configuration. `deploy-terraform.sh` installs the new provider version from the lock file; direct Terraform deployments must run `terraform init` before the next plan or apply.

### Changed

- **Model prices and model lists are no longer hard coded into the platform.** Token prices are read from the AWS Price List API for the inference region, refreshed every hour, and stored in the existing `model-pricing` parameter; the static price table and the built-in Codex model list are removed. A model without a published price shows its cost as unavailable, and the model pickers show "Cost estimate unavailable for this model" below it when it is selected. A model list that cannot be read shows the last list read, with a note in every picker, or a text field; Codex no longer falls back to a built-in list. Limits are listed under [Where prices come from](docs/using-the-platform/intent-observability.md#where-prices-come-from).
- **Contributor workflows provide automated PR quality reports, coverage and dependency comparisons**, impact maps, area and size labels, and a shared PR template with stronger checks ([#703](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/703), [#661](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/661), [#655](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/655), [#630](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/630)).
- Personal agent credential changes show a confirmation only when already-started work is affected, with clearer descriptions of the impact ([#699](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/699)).
- **Token usage is measured from CLI output across author, reviewer, support, repair and conflict-resolution calls.** Accounting distinguishes cache reads and writes, sums OpenCode steps and avoids counting restored Codex usage twice ([#686](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/686), [#669](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/669)).
- Main deployments request post-deployment release tests ([#679](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/679)).
- **Jira project bindings use explicitly delegated space connections**, allowing all authorized members and delivery synchronization to access the project without individual Jira connections ([#673](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/673)).
- Engine-owned Git commits use Conventional Commits, based on a validated description supplied by the stage's author. Tracker issue keys are included where applicable ([#658](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/658)).
- **CodeCommit setup moved from a per-user role handshake to a single platform connection.** A platform admin sets one IAM role ARN and region in **Admin → Source Control → AWS CodeCommit** ("Test & save"), and every space uses it; space creators pick CodeCommit repositories from the same generic list as the other providers, with no ARN, region, external ID or IAM to supply. The external ID is now one value per deployment (`aidlc:<uuid>`, provisioned by Terraform) instead of one per user. Which repositories a space may use is controlled by tagging each repository `aidlc=true` (an explicit repository-ARN list is an equally supported, more locked-down variant); the setup guide adds a concrete deny that limits who may set the tag ([#531](https://github.com/aws-samples/sample-collaborative-ai-dlc/issues/531)).
- **AWS SDK requests identify the platform and release through a versioned application user agent**, without user-identifying information ([#568](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/568)).
- **Updated Claude Code, Codex, Kiro and OpenCode CLIs.** Kiro uses its v2 engine with structured streaming, credit reporting and durable session persistence ([#519](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/519)).

### Notes

- **Costs after upgrading.** The stored price table changes format and the previous one is not read, so costs show as unavailable until the first price refresh: at most one hour after the upgrade, or as soon as someone opens a model picker in Admin or in Space Settings → Agent. Some costs change because prices are now the published ones for the inference region (for example Claude Sonnet 4.6 through a `us.`/`eu.` profile is priced at the In-Region rate instead of the Global one). Usage with cache writes on GPT-5.5 or GPT-5.4 shows its cost as unavailable, because AWS publishes no cache-write rate for these models.
- **AI-DLC version selection.** Standard deployments prepare all eight supported official catalogs and enable version selection by default, while preserving an explicit `aidlc_release_pinning = "off"` setting and the existing Stable assignment. Preparation does not approve a new version or make it Stable. Existing intents keep their pinned closure. Deploy the backend and frontend together; direct Terraform deployments must also run `scripts/prepare-aidlc-releases.mjs` ([#701](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/701)).
- **Sandboxing scope.** SRT is off by default and applies to agent processes, their child processes, script sensors and MCP connection checks. Engine-owned Git and AWS operations remain outside that sandbox. Started intents retain the policy captured at their first start ([#696](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/696)).
- **Jira bindings after upgrading.** Existing bindings require an owner or admin to use **Reconnect** and explicitly confirm delegation once. Until then, browsing requires reconnection and delivery synchronization remains queued without consuming retries. Deploy the projects, trackers and users Lambdas together with the frontend; no table migration is required ([#673](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/673)).
- **IAM role paths.** Changing `iam_role_path` on an existing deployment replaces IAM roles because their paths are immutable. Adding or changing only a permissions boundary is an in-place update ([#603](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/603)).
- **Upgrade from v2.2.0.** Spaces bound under the previous per-user CodeCommit role keep working: a binding keeps the role it was verified with, so nothing stops at upgrade and there is nothing to rebind. To move a space onto the shared platform connection, a platform admin first sets the connection (**Admin → Source Control → AWS CodeCommit**), then a space owner runs the existing **Rebind and verify** on its repositories. The per-user role form is gone, so an **invalidated** old binding can only recover by moving to the platform connection, which requires that connection to be set first. Any later save of a space's source control (a rebind, a new repository, another provider's auth type) verifies every CodeCommit repository against the platform connection: set the connection first, and make sure its role reaches the space's existing repositories, or the save returns 409.
- Known limits (documented, not coded): all spaces share one role, so if its trust breaks every CodeCommit operation fails until the admin fixes it, while bindings stay active; **"Test & save"** proves the trust for the `codecommit` Lambda principal only, so a trust policy missing the broker or source-control principal passes but then fails at bind (409) or at run time; removing the `aidlc` tag during a run invalidates a binding only on a denied repository, content or Git call (a pull-request-only denial fails just that operation and keeps the binding); a re-run after a role change may open a second pull request for tracker-linked intents that stored the old pull-request number; and, like the GitHub App picker, the repository list checks only the first 1,000 repositories of the account and region (in name order), so a readable repository beyond that is not listed.
- **REST API access with WAF.** API clients must use the application's CloudFront endpoint when WAF is enabled; authenticated requests sent directly to the REST API without the origin-verification header are blocked ([#573](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/573)).
- **Parked Kiro sessions.** Older Classic sessions on the Standard runtime cannot be loaded by the new v2 engine. Recovery starts a fresh conversation with the saved human answer and preserves committed work, but the old conversation context is lost once. Managed environments retain their pinned runtime until rebuilt ([#519](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/519)).
- **Existing HTTP MCP servers.** Change remote MCP URLs to HTTPS or remove them, including loopback HTTP endpoints. Stored configurations are revalidated before stage launch or resume ([#507](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/507)).
- **Yjs rollout and sizing.** Clustering remains opt-in. Production worker defaults increase to 1,024 CPU units and 2,048 MiB of memory; explicit sizing overrides are retained. A standalone-to-cluster transition requires one fixed worker with `mode_transition = true` before expanding the fleet. See the [Yjs operations guide](docs/development/yjs-operations.md) ([#457](https://github.com/aws-samples/sample-collaborative-ai-dlc/pull/457)).

- Phase 4 tracker-migration polish (#198): an Admin → Tracker Migration card surfaces the count of projects + sprints still on the legacy tracker shape and promotes the bulk migration from the CLI-only `migrate-tracker-fields` Lambda to a one-click button. Docs (`using-the-platform/git-integration.md`, `getting-started/setup.md`) gained a "Migrating from legacy issue integration" section.
- GitLab.com support as an alternative git provider (#3). GitLab can now be selected as a project's **code host** (clone/branch/file browse, push, merge-request creation, MR-comment read/write during review) and as an **issue tracker** (`gitlab-issues`) so a sprint can be started from a GitLab issue — at parity with GitHub. Backed by a shared git-provider abstraction (`lambda/shared/git-providers`) and a unified frontend git service so GitHub and GitLab share one code path. GitLab's short-lived OAuth access tokens are refreshed automatically for long-running construction jobs. Docs (`README`, `getting-started/setup.md`, `using-the-platform/git-integration.md`) updated for the new provider.

### Notes

- V1 sprints are view-only in v2. Continue active v1 work with release `v1.1.0` before upgrading.
- The v1-to-v2 update removes the retired ECS runtime and agent-pool table. All other application data remains in place, but operators remain responsible for application-data backups beyond the automatic Terraform state backup.
- Claude runtime model override is **fully backward compatible and opt-in**. A Claude project with no model override resolves to exactly the same model as before (the static `ANTHROPIC_MODEL` task-definition default, e.g. `us.anthropic.claude-sonnet-4-6`) — `resolveModel` falls through the empty per-job `AGENT_MODEL` to that static value. Existing kiro/opencode overrides and stored `cli_models` data are untouched (the `claude` key is purely additive). Mixed-version deployments degrade safely: an old worker image ignores a dispatched Claude model and uses its driver default; an old frontend against the new backend simply doesn't render the Claude model field; a new frontend against an old backend sees `runtimeModelOverride.claude:false` and disables the field. No migration is required for OSS forks — behavior changes only when a user explicitly sets a Claude model.
- No legacy code is removed by Phase 4. The `issue_integration_enabled` boolean, `issue_number` / `issue_url` Sprint fields, dual-shape readers, the per-project `MigrateTrackerCard`, the per-project `POST /projects/:id/migrate-tracker` endpoint, and the bulk `migrate-tracker-fields` Lambda all stay deployed indefinitely as safety nets for OSS forks on their own upgrade timelines.
- GitLab support is additive and provider-scoped. Existing GitHub projects are unaffected: a git connection is bound to its provider, so a GitHub connection only serves GitHub projects and a GitLab connection only serves GitLab projects. GitLab OAuth credentials are optional — if an operator doesn't configure them, the **Connect GitLab** button stays disabled and GitHub behaves exactly as before.
